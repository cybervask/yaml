# Smart Go-YAML Engine

[![Go CI/CD Pipeline](https://github.com/cybervask/yaml/actions/workflows/go.yml/badge.svg)](https://github.com/cybervask/yaml/actions/workflows/go.yml)

Другие языки: [English (EN)](README.md) | [中文 (ZH)](README.zh.md) | [日本語 (JA)](README.ja.md) | [Español (ES)](README.es.md)

Надежная и высокопроизводительная бесшовная замена для `go.yaml.in/yaml/v4`. Пакет полностью сохраняет оригинальные сигнатуры функций и ключевые опции (`Option`), автоматически интегрируя глубокую рекурсивную подстановку значений по умолчанию (`default:"value"`), нативную инъекцию переменных окружения ОС (`env:"VAR"`), автоматическую генерацию справочного текста для CLI (`Help()`) и строгую валидацию полей на основе тегов (`validate:"..."`) прямо на уровне парсинга.

## Доступные правила валидации и возможности

Вы можете комбинировать несколько правил валидации внутри одного тега `validate`, используя запятую в качестве разделителя (например, `validate:"not_empty,endpoint"`).

> **Примечание о циклических структурах:** программно собранные циклические структуры указателей (например, узел, ссылающийся сам на себя) не приводят к зависанию `Validate` — рекурсия по текущему пути возвращает явную ошибку `cyclic structure detected` для ссылающегося поля. Общие (ациклические) сабобъекты, на которые ссылается несколько полей, остаются валидными. В выводе `Help` самоссылающийся тип документируется один раз на путь, а рекурсия в него тихо пропускается.

> **Примечание о лимитах границ:** значение лимита, которое не удаётся разобрать (например, `validate:"minlen=abc,maxlen=5"`), сообщается как явная ошибка конфигурации с именем правила (`invalid validator configuration: minlen "abc": ...`) — невалидный лимит никогда не отключает свою проверку молча. То же относится к boundary-правилам (`min`, `max`, `gt`, `lt`) на нечисловых типах (например, `bool`): проверка неприменима, поэтому она сообщается как ошибка конфигурации, а не тихо пропускается.



| Правило / Возможность     | Пример синтаксиса                  | Описание                                                                                                                             | Поддерживаемые типы                       |
|:--------------------------|:-----------------------------------|:-------------------------------------------------------------------------------------------------------------------------------------|:------------------------------------------|
| **Инъекция окружения**    | `env:"APP_PORT"`                   | **12-Factor App:** Динамически внедряет переменные среды системы. По умолчанию переменная окружения имеет абсолютный приоритет над значениями из YAML и тегов default; арбитраж источника доступен через тег `priority` (см. **Приоритет источника**). Теги `default` и `env` применяются к скалярным полям. Поддерживает значения `time.Duration`. В load-путях (`LoadFile`, `Load`, `Loader.Load`, `Decoder.Decode`) невалидное env-значение сообщается как ошибка; автономный вызов `SetDefaults` сохраняет legacy-тихое поведение — невалидное env-значение оставляет поле нулевым без ошибки, а тег `default` не применяется (единственное исключение: невалидный литерал `time.Duration` сообщается как ошибка). | `string`, `bool`, примитивные числа, `time.Duration` |
| **Приоритет источника**   | `priority:"value"`                 | **Тег арбитража env:** применяется к полям, у которых также есть тег `env`; значения — `value` или `env`. По умолчанию (без тега или `priority:"env"`) переменная окружения имеет абсолютный приоритет над значением из YAML и тегом `default`. При `priority:"value"` поле, ненулевое после применения default'ов и decode — значение из YAML, применённый ненулевой тег `default` или предзаполненное программно значение — побеждает непустую переменную окружения; если источник один, он применяется независимо от тега. Поле, остающееся нулевым после default'ов и decode (явный ноль в YAML или нулевой тег `default`, например `default:"0"`, `default:"false"`, `default:""`), не считается значением для арбитража — применяется переменная окружения. Неизвестное значение тега и `priority` без `env` сообщаются как ошибки конфигурации независимо от наличия значения/env. Как и `default` и `env`, тег `priority` применяется к скалярным полям; на нескалярном поле (struct, slice, map) он сообщается как ошибка конфигурации. | `string`, `bool`, примитивные числа, `time.Duration` |
| **Обязательное поле**     | `validate:"required"`             | Гарантирует, что полю присвоено ненулевое значение. Взаимоисключающе с тегом `default`. `not_empty` — устаревающий алиас (сохранён для обратной совместимости, планируется к деприкации). | `string`, `struct`, `slice`, `map`, числа |
| **Условная валидация**    | `validate:"required_if=role!=srv"` | **Кросс-полевая проверка:** Поле становится обязательным на основе значения другого поля. Канонические операторы: `==` (равно), `!=` (не равно) — сравнение без учёта регистра; `~=` (совпадение с регекспом) и `^=` (не совпадение) — закавыченные шаблоны освобождаются от кавычек. Простое имя таргета ищется сначала в объемлющей структуре, затем в корне; dot-путь (`required_if=server.mode==prod`) адресует от корня; указатели-таргеты разыменовываются. Несуществующий таргет и невалидный регексп — ошибки конфигурации. Значение `required_if` без распознанного оператора — ошибка конфигурации. Legacy-форма через двоеточие (`key:value`, `key:!value`, макросы `:empty`/`:not_empty`) устарела (deprecated), но продолжает работать. | `string`, числа, `bool`, указатели и др.  |
| **Белый список (Выбор)**  | `validate:"choice=dev,prod"`       | **Режим whitelist:** Строковое значение должно строго соответствовать одному из токенов. Рекурсивно поддерживает элементы слайсов.   | `string`, `[]string`                      |
| **Черный список (Выбор)** | `validate:"choice=!red,!black"`    | **Режим blacklist:** Разрешает любое строковое значение, кроме специфических исключений, начинающихся с `!`.                         | `string`, `[]string`                      |
| **Диапазоны и Время**     | `validate:"min=1s,max=10m"`        | Задает **включающие** нижнюю (`>=`) и верхнюю (`<=`) числовые границы. Нативно поддерживает числа и интервалы `time.Duration`.       | `int`, `uint`, `float`, `time.Duration`   |
| **Строгое сравнение**     | `validate:"gt=5,lt=10"`            | Задает **исключающие** строгие границы: больше (`>`) и меньше (`<`). Поддерживает `time.Duration`.                                   | `int`, `uint`, `float`, `time.Duration`   |
| **Длина строки (Руны)**   | `validate:"minlen=3,maxlen=20"`    | Задает лимиты на длину строки. Профессионально учитывает **Unicode руны (символы)**, а не сырые байты.                               | `string`                                  |
| **Размер коллекции**      | `validate:"mincount=1,maxcount=5"` | Задает минимальное и максимальное количество элементов внутри динамических коллекций.                                                | `slice`, `map`                            |
| **Сетевые форматы**       | `validate:"format=ipv4"`           | Валидирует IP сети. Поддерживает `format=ip`, `format=ipv4` и `format=ipv6`. Взаимоисключающе с опциями `endpoint` и `url`.          | `string`                                  |
| **Hex-кодирование**       | `validate:"format=hex"`            | Валидирует hex-строки: декодируются через `hex.DecodeString` с чётным числом символов. Нечётная длина и не-hex символы отбиваются.   | `string`                                  |
| **Проверка UUID**         | `validate:"format=uuid"`           | Проверка канонической формы UUID (hex 8-4-4-4-12 с дефисами); версия и вариант (RFC 4122) НЕ верифицируются.                                                | `string`                                  |
| **Регулярное выражение**  | `validate:"regexp=^[a-z]{2,4}$"`   | Проверяет соответствие строки шаблону регулярного выражения. Безопасно к запятым внутри паттерна. Внешние кавычки (`'...'` или `"..."`) срезаются с паттерна; для матча литеральной кавычки берите ограничитель другого типа (например, `regexp="^'q'$"`). | `string`, `[]string`                      |
| **Сетевой эндпоинт**      | `validate:"endpoint"`              | Проверяет стандартные сетевые адреса (`host:port`). Нативно валидирует синтаксис **IPv6** и границы портов (1-65535).                | `string`                                  |
| **Проверка URL**          | `validate:"url"`                   | Проверяет валидность URI. Строго требует явного указания разделителя протокола (схемы) (например, `http://`, `grpc://`) и непустого хоста: значения только со схемой (`http://`) отклоняются.             | `string`                                  |
| **Path-правила per-instance** | `validate:"min_len.min=0,max_len.max=64"` | **Общие вложенные типы:** Применяет правило к вложенному полю конкретного экземпляра через синтаксис `<yaml_путь>.<правило>=<значение>`; у каждого родительского экземпляра свои границы. Висячие пути сообщаются как ошибки. Значения path-правил могут содержать точки. | вложенные поля struct |

## Загрузка и дамп

- **Опции действуют end-to-end:** каждая опция, переданная в `Load` / `LoadFile` (например, `WithKnownFields`, `WithUniqueKeys`), применяется и на parse-стадии AST, и на финальной decode-стадии в целевую структуру — строгая проверка работает так же, как в upstream `yaml4.Load`. Форматные опции (`WithIndent` и др.) на загрузку не влияют.
- **Write-back `!include` привязан к объекту:** `DumpWithInclude` берёт пути записи из include-данных, записанных при загрузке именно этого объекта, — передавайте в `DumpWithInclude` тот же указатель, что и в `Load` / `LoadFile`. Структура, не проходившая такую загрузку (или копия загруженного значения), дампится в безопасном режиме: значения выводятся инлайн, маркеры `!include` не создаются, файлы не изменяются.
- **`!include` резолвится всеми путями загрузки:** `LoadFile` разрешает директивы `!include` относительно каталога конфиг-файла, а `Load`, `Loader.Load` и `Decoder.Decode` — относительно текущей рабочей директории. Потоковые пути не биндят include-сессию к целевому объекту, и успешная потоковая загрузка указателя, ранее загруженного через `Load`/`LoadFile`, снимает прежнюю привязку: объект дампится в inline safe mode (см. буллет про write-back выше).
- **Один документ на файл-цель:** файл-цель `!include` должен содержать ровно один YAML-документ — завершающий маркер документа `---` приводит к ошибке загрузки (`included file ... contains multiple documents`). Для главного конфига действуют семантики upstream yaml4: одноходовые пути (`LoadFile`, `Load`, `Unmarshal`) также отвергают завершающий маркер `---` (`expected single document, found multiple`), а потоковые пути (`Loader.Load`, `Decoder.Decode`) читают только первый документ и молча отбрасывают остальные.

## Профили конфигурации (Валидные и невалидные случаи)

### Пример 1: Стандартный конфиг приложения с выводом справки (Валидный профиль)
**Спецификация YAML (`config.yaml`):**
```yaml
env: "prod"
api_url: "https://cybervask.net"
api_endpoint: "127.0.0.1:443"
server:
  logging:
    colors: true
    level: "warn"
  allowed_ips:
    - "192.168.1.1"
```

**Модель конфигурации Go-приложения:**
```go
package main

import (
	"fmt"
	"time"

	"github.com/cybervask/yaml"
)

type TLS struct {
	MinVersion string   `yaml:"min_version" default:"tls1.3" validate:"choice=tls1.2,tls1.3" env:"TLS_MIN_VERSION" description:"Минимальная поддерживаемая версия TLS"`
	Alpn       []string `yaml:"alpn" default:"h2,http/1.1" validate:"choice=h2,http/1.1" description:"Application-Layer Protocol Negotiation"`
}

type Logging struct {
	Level         string           `yaml:"level" default:"info" validate:"choice=debug,info,warn" description:"Уровень выполнения иерархии логов"`
	Colors        bool             `yaml:"colors" description:"Включить ANSI цветной вывод логов"`
	Timeout       string           `yaml:"timeout" default:"5s" description:"Внутренний таймаут обработки запроса"`
}

type Config struct {
	Env          string        `yaml:"env" default:"dev" validate:"choice=dev,stage,prod" description:"Окружение выполнения приложения"`
	AppName      string        `yaml:"app_name" default:"api" validate:"minlen=3,maxlen=10" description:"Внутреннее имя (моникер) приложения"`
	APIUrl       string        `yaml:"api_url" validate:"url,required_if=env==prod" env:"API_URL" description:"Базовый URL целевого API"`
	APIEndpoint  string        `yaml:"api_endpoint" validate:"endpoint" description:"Локальный сетевой эндпоинт для привязки сокета"`
	Timeout      time.Duration `yaml:"timeout" default:"5s" validate:"min=1s,max=10m" description:"Глобальный таймаут отслеживания жизненного цикла запроса"`
	Crypto       TLS           `yaml:"crypto" description:"Слой конфигурации структуры безопасности TLS"`
	Server       struct {
		Logging    Logging  `yaml:"logging" description:"Параметры логирования сервера"`
		AllowedIPs []string `yaml:"allowed_ips" validate:"mincount=1,maxcount=10" description:"Белый список IP-адресов удаленных узлов"`
	} `yaml:"server"`
}

func main() {
	var cfg Config
	yaml.Help(cfg)
}
```

**Автоматический интерактивный вывод CLI-справки (`yaml.Help(cfg)`):**

Самоссылающиеся типы структур документируются один раз на путь — рекурсивная ветка тихо пропускается, поэтому `Help` всегда завершается.
```text
yaml configuration schema documentation:

env:             Окружение выполнения приложения (default: dev, validate: [choice=dev,stage,prod])
app_name:        Внутреннее имя (моникер) приложения (default: api, validate: [minlen=3,maxlen=10])
api_url:         Базовый URL целевого API (env: API_URL, validate: [url,required_if=env==prod])
api_endpoint:    Локальный сетевой эндпоинт для привязки сокета (validate: [endpoint])
timeout:         Глобальный таймаут отслеживания жизненного цикла запроса (default: 5s, validate: [min=1s,max=10m])
crypto:          Слой конфигурации структуры безопасности TLS
  min_version:   Минимальная поддерживаемая версия TLS (env: TLS_MIN_VERSION, default: tls1.3, validate: [choice=tls1.2,tls1.3])
  alpn:          Application-Layer Protocol Negotiation (default: h2,http/1.1, validate: [choice=h2,http/1.1])
server:
  logging:       Параметры логирования сервера
    level:       Уровень выполнения иерархии логов (default: info, validate: [choice=debug,info,warn])
    colors:      Включить ANSI цветной вывод логов
    timeout:     Внутренний таймаут обработки запроса (default: 5s)
  allowed_ips:   Белый список IP-адресов удаленных узлов (validate: [mincount=1,maxcount=10])
```

### Пример 2: Нарушение правил белого списка Choice (Невалидный профиль)
**Спецификация YAML (`config.yaml`):**
```yaml
env: "testing" # Ошибка: значение "testing" выходит за рамки белого списка [dev, stage, prod]
```
**Строка ошибки рантайма приложения (`err.Error()`):**
```text
field env: value "testing" is invalid; allowed choices are [dev, stage, prod]
```

### Пример 3: Накопление множественных ошибок, лимитов строк, коллекций и времени (Невалидный профиль)
**Спецификация YAML (`config.yaml`):**
```yaml
env: "prod"
app_name: "go"         # Ошибка 1: длина в символах меньше minlen=3
api_url: ""            # Ошибка 2: условное правило выполнилось (env==prod), но поле пустое
timeout: "500ms"       # Ошибка 3: нарушено строгое ограничение по времени min=1s
server:
  logging:
    level: "debug"     # (Валидно)
  allowed_ips: []      # Ошибка 4: размер коллекции равен 0, что нарушает mincount=1
```
**Строка агрегированной ошибки рантайма приложения (`err.Error()`):**
```text
field app_name: string length 2 is less than minlen 3
field api_url: is required when field env==prod
field timeout: value 500ms < min 1s
field server.allowed_ips: collection size 0 is less than mincount 1
```

## Примеры

В директории `examples/` находятся запускаемые программы, покрывающие все правила валидации и возможности библиотеки. Запускать из корня репозитория:

```bash
go run ./examples/01_choice
```

| Пример | Демонстрирует |
|--------|---------------|
| `01_choice` | Белые/чёрные списки `choice`, значения с запятыми в кавычках, валидный и невалидный профили |

| `03_min-max` | Включающие границы `min`/`max` для чисел и `time.Duration`, валидный и выходящий за границы профили |

| `06_with-include` | Разрешение директивы `!include` при загрузке, включая ошибку отсутствующего файла |
